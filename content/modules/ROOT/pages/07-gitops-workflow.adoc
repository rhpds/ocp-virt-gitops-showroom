= GitOps Workflow and VM Access
:source-highlighter: rouge


== Clone the Apps repository

If you have not cloned the Apps repo yet, follow xref:02-details.adoc[Workshop Details], then:

[source,role="execute"]
----
cd ~/ocp-virt-gitops-apps
----

== Development process

[source,role="execute"]
----
git checkout vms-dev
----

Make changes to base templates or overlays, then commit and push:

[source,role="execute"]
----
git add .
git commit -m "Update VM configuration"
git push origin vms-dev
----

After the push, sync the Argo CD Application `workshop-gitops-vms-dev` (automatic sync is disabled).

== Promotion to homologation

[source,role="execute"]
----
git checkout vms-hml
git merge vms-dev
git push origin vms-hml
----

Then sync `workshop-gitops-vms-hml`.

== Promotion to production

[source,role="execute"]
----
git checkout vms-prd
git merge vms-hml
git push origin vms-prd
----

Then sync `workshop-gitops-vms-prd`.

== SSH access to VMs

VMs are automatically configured with SSH key access:

[source,role="execute"]
----
virtctl ssh cloud-user@<vm-name>
----

Example for the development web VM:

[source,role="execute"]
----
virtctl ssh cloud-user@dev-vm-web-01 -n workshop-gitops-vms-dev
----

== Service verification

Each environment exposes VM services for external access:

[source,role="execute"]
----
oc get svc -n workshop-gitops-vms-dev
oc get svc -n workshop-gitops-vms-hml
oc get svc -n workshop-gitops-vms-prd
----

Services target `kubevirt.io/domain` labels. Verify labels:

[source,role="execute"]
----
oc get pods -n workshop-gitops-vms-dev --show-labels | grep kubevirt.io/domain
oc get svc vm-web-service -n workshop-gitops-vms-dev -o yaml | grep selector -A 3
----
