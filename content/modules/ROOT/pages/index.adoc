= OpenShift Virtualization GitOps Workshop
:source-highlighter: rouge

This workshop demonstrates how to implement GitOps principles for managing Virtual Machines (VMs) in OpenShift Virtualization using OpenShift GitOps (Argo CD).

== How to use this guide

Follow the modules in order. Each demo builds on the previous one.

**Before any demo**, complete the required setup on this page (`oc login` and `git config`) and xref:02-details.adoc[Workshop Details] (Application sync and Apps repo clone).

. xref:01-overview.adoc[Workshop Overview] -- learning objectives, architecture, and environments
. xref:02-details.adoc[Workshop Details] -- verify the pre-provisioned lab, clone the Apps repo, and demo summaries
. xref:03-demo-01-manual-change.adoc[Demo 1] -- manual change detection and drift correction
. xref:04-demo-02-vm-recovery.adoc[Demo 2] -- VM recovery from data loss
. xref:05-demo-03-add-development-vm.adoc[Demo 3] -- adding a new development VM via Git
. xref:06-demo-04-multi-env-management.adoc[Demo 4] -- multi-environment management with Kustomize
. xref:07-gitops-workflow.adoc[GitOps Workflow] -- promotion flow and VM access
. xref:08-troubleshooting.adoc[Troubleshooting] -- monitoring and common issues
. xref:99-conclusion.adoc[Cleanup] -- demo reset notes and best practices

== Lab identity

Your lab GUID is `{guid}`. It identifies this environment. Git branches for VMs are `vms-dev`, `vms-hml`, and `vms-prd`.

== OpenShift CLI access

The Showroom terminal starts as a limited service account. Log in as the lab admin before running workshop commands:

[source,subs="attributes+",role="execute"]
----
oc login -u {openshift_cluster_admin_username} -p '{openshift_cluster_admin_password}' --server={openshift_api_server_url} --insecure-skip-tls-verify=true
----

Confirm the current OpenShift user:

[source,role="execute"]
----
oc whoami
----

List Argo CD Applications for the workshop:

[source,role="execute"]
----
oc get applications -n openshift-gitops
----

Expected: `oc whoami` returns `{openshift_cluster_admin_username}`, and the Applications list shows `workshop-gitops-vms-dev`, `workshop-gitops-vms-hml`, and `workshop-gitops-vms-prd`.

== Git author identity (required)

The Showroom terminal has **no** Git `user.name` or `user.email`. Without these, every `git commit` fails and Demo 3 / Demo 4 cannot push. Run both commands once at the start of the lab:

Configure Git user name:

[source,role="execute"]
----
git config --global user.name "Lab User"
----

Configure Git user email:

[source,role="execute"]
----
git config --global user.email "lab-user@example.com"
----
